# rsync

当前正式版本：**1.0.0**。

`rsync` 是 Linux 上一主一从的单向文件同步程序。主机提供 Web 管理页并主动连接只监听同步端口的从机。主机新增的文件会复制到从机，同路径普通文件按主机内容更新；主机删除此前同步过的文件或目录时，从机也会清理已记录的文件和空目录，从机独有内容保留。覆盖或删除文件前默认把旧版本放入保留 7 天的历史目录，可在从机配置中关闭历史备份。它不兼容 Syncthing 协议。

## 构建

需要稳定版 Rust 工具链。在项目目录运行：

```sh
cargo build --release --locked
```

生成的程序是 `target/release/rsync`。Linux 也有名为 `rsync` 的系统命令；建议使用本程序的绝对路径，避免覆盖系统命令。状态目录为同步根目录下的 `.rsync`。升级现有部署时保留该目录，不要重新执行 `init`。

本仓库只包含 Rust 源码、网页资源、构建配置和使用文档，不包含预编译程序、同步数据、状态数据库或节点证书。请在目标 Linux 环境按上述命令编译；`Cargo.lock` 固定依赖版本，`target/` 和本地发布目录 `dist/` 不纳入版本管理。

### 状态存储与升级

1.0.0 使用数据库结构版本 1、同步协议版本 5。主机文件清单存于 `source_entries`，未确认任务存于 `source_outbox`；从机文件归属与校验状态存于 `replica_files`，目录归属存于 `managed_dirs`，断点及发布意图存于 `staging`。运行状态与校验进度标记存于 `kv`，节点配置存于 `.rsync/config.toml`。初始化会创建当前结构，主机打开状态库时会确保任务表存在；不包含旧结构迁移逻辑。

升级现有当前结构的部署时，保留同步根目录及 `.rsync`，先更新主机程序，再通过网页一键升级从机，或按[从机手动升级教程](从机部署教程.txt)操作。不需要重新初始化、交换证书或重建数据库。替换主机程序后需要重启主机服务；一键升级从机会由其 systemd 服务自动重启。两端须支持相同的同步协议，建议使用同一发布版本。

主机的 `source_outbox(kind, path)` 只存未确认的任务路径：`0` 为发布文件或目录、`1` 为删除文件、`2` 为删除目录，联合主键去重；文件大小、哈希与分块信息仍只存于 `source_entries`。扫描在同一事务中更新元数据和任务，先发送删除、再发送新增或更新。收到从机批次确认后删除对应任务；确认丢失时允许幂等重发，最终整轮确认丢失时用空增量完成代次提交。任务不会追加为历史日志，成功后清空。整轮同步成功后，从机也会清理因源文件删除、截断或软链接替换而废弃的暂存数据。

## 首次配置

下面的目录和地址仅作示例。两台机器分别执行：

```sh
# 从机：监听自己的同步端口；0.0.0.0 表示全部 IPv4 网卡
rsync init --role replica --root /data/replica --addr 0.0.0.0:22000
# 主机：可以先不指定连接目标，启动 Web 后再填写
rsync init --role source --root /data/source --web-addr 0.0.0.0:8787
```

`init` 会打印 CA 证书路径和指纹。通过可信渠道把各自的 `.rsync/ca.pem` 复制给对方，人工核对指纹。从机必须导入主机 CA；主机可使用网页导入从机 CA 和设置连接目标，也可分别在命令行导入：

```sh
rsync peer-add --root /data/source --cert /tmp/replica-ca.pem --fingerprint <从机指纹>
rsync peer-add --root /data/replica --cert /tmp/source-ca.pem --fingerprint <主机指纹>
```

从机运行 `rsync run --root /data/replica` 后开始监听；主机运行 `rsync run --root /data/source` 后先提供 Web 页面。未设置目标地址时主机不发起同步连接；在网页“连接设置”填入从机 IP 与端口并配对证书后，主机会主动连接，但新建主机**不会立刻同步**。先设置排除规则、检查两端目录，再点击“确认并开始首次同步”。重新初始化的主机同样需要首次同步确认。初始化主机时如明确要自动开始，可加 `--start-immediately`。启动顺序不限；连接或文件同步持续失败时，主机按 0.25～5 秒逐步退避重试，成功同步后复位；相同连接或同步错误在 60 秒内合并记录。主机关机时从机继续监听并保留现有文件。主机持续监听本地文件变化，变化时发送增量清单，默认每 24 小时完整扫描并校对一次。`rsync status --root <目录>` 查看最近同步结果。`rsync run --root /data/source --once` 是显式执行一轮同步，会跳过首次确认；要求已设置目标并配对证书，建立连接阶段最多等待 30 秒，且不能与常驻主机进程同时运行；同步耗时取决于数据量与网络。

## 主机 Web 管理

常驻主机启动后，能访问主机的设备可打开 `http://主机IP:8787/`，将“主机IP”替换为实际可达地址。控制台是单页布局，可以查看从机连接、实时传输速度、错误、排除规则，也可以立即同步、暂停或恢复自动同步。空闲时速度显示 0 B/s。暂停在当前传输结束后生效；暂停期间仍可点击“立即同步”执行一次。排除规则可填写相对路径，或用 `**/目录名` 排除同步根目录任意层级的同名目录。页面“待校对文件”包括已同步、无需再次传输的文件，全量校对结束后归零。

页面的“连接设置”可填写或清空主机的目标 IP 与端口；切换目标后主机会断开旧连接并重连。连接另一台使用不同 CA 的从机时，展开“更换从机证书”，核对指纹后导入其 CA；网页可下载主机 CA，仍需在从机上使用 `peer-add` 信任主机。每次只连接一台已配对的从机。

“主机配置”和“从机配置”卡片可分别修改主机的全量扫描周期、哈希线程上限、完整校验周期，以及从机的历史保留天数、完整校验周期。从机卡片内的“历史备份”开关独立保存，无需点击“保存从机配置”；关闭后，新的同路径覆盖不再保存旧版本。再次打开开关时默认保留 7 天，也可修改保留天数后另行保存。把历史保留设为 0 同样会关闭备份。已存在的历史文件仍保留在 `.rsync/history/`，不会因关闭开关而自动删除；如需释放旧备份占用的空间，需自行确认后清理。每轮同步成功后，从机清理已不再需要的 `.rsync/tmp/*.part` 暂存文件；完整校对成功后还会尝试收缩状态数据库日志。同步中断时保留暂存文件供续传。从机设置只在连接时可保存，经现有双向 TLS 同步连接发送；从机仍不运行 Web 服务。两端的同步根目录由初始化和启动时的 `--root` 决定，页面只显示当前值；迁移根目录需停止服务、移动目录（包括 `.rsync`）、更新配置中的 `root` 与启动参数，再重启验证。从机监听地址和主机 Web 监听地址也只显示当前值，可在对应节点的 `.rsync/config.toml` 中修改并重启。设置输入有范围校验，保存后在下一轮同步生效；同步正在进行时，从机设置请求可能需要等待，超时后可重试。

### 从机一键升级

主机页面“从机配置”显示双方程序版本和“一键升级”。点击后需在弹窗确认；主机从**当前运行的程序**读取升级包，经现有双向 TLS 连接发送，不接受网页上传的文件或执行任意命令。升级请求会在当前文件传输的安全检查点中断本轮同步，然后优先处理。页面显示传输进度及从机重连结果。若两端程序内容相同，则不重启。

从机由 `systemd` 托管且设置 `Restart=always`，才能使用页面一键升级。接收端限制程序大小为 128 MiB，校验 BLAKE3 哈希和新程序的 `rsync --version` 运行结果，然后在程序目录保留一份 `rsync.previous` 并原子替换 `rsync`。从机退出后由 `systemd` 重启，主机在重新连接并确认版本后显示成功。协议或必要能力不匹配时文件同步暂停，两端升级一致后恢复。

当前 Web 不设登录门禁；任何能打开该页面的局域网设备也能确认并触发从机升级或重启。升级接口额外要求浏览器同源请求。请将 Web 端口限制在可信网络内。

Web 默认监听 `0.0.0.0:8787`，即主机所有 IPv4 网卡。初始化时可以用 `--web-addr` 改变监听地址或端口。网页不设登录门禁；任何能连接这个端口的人都能查看状态并操作同步。页面不使用表单令牌。服务会检查 Host、拒绝浏览器标记为跨站的写入请求，并校验操作与路径；表单操作在当前页面完成，不会因保存跳回页首；成功和失败都会在页面下方短暂显示提示。旧浏览器若不发送 `Sec-Fetch-Site`，无法获得这层跨站保护。HTTP 本身不加密，因此不要把 Web 端口映射到公网。

主机的目标 `addr` 应设置为从机可达的 IP 与端口，格式为 `从机IP:22000`；从机的监听 `addr` 可设为 `0.0.0.0:22000`。若主机防火墙启用，还需放行 Web 端口的局域网访问。主机处于无法从外部直接访问的虚拟机时，仍可主动连接从机；Web 页只能从能访问该虚拟机的网络进入。从机是公网地址时，防火墙和云安全组应按主机实际公网出口 IP 放行同步端口，不能用主机的内网地址作为来源限制。

## 排除文件和目录

在主机配置相对于同步根目录的路径。目录规则会排除整棵子树；`**/目录名` 会排除任意层级的同名目录，也不需要在从机重复配置。

```sh
rsync exclude-add --root /data/source cache
rsync exclude-add --root /data/source '**/.vscode'
rsync exclude-add --root /data/source docs/private.txt
rsync exclude-list --root /data/source
rsync exclude-remove --root /data/source cache
```

也可以编辑主机的 `.rsync/config.toml` 中的 `excludes = ["cache", "docs/private.txt"]`。运行中的主机会在配置变更后重新扫描；网页上也能直接编辑规则。同步过程中发生普通文件变化时，先记下变更路径，当前轮次结束后只扫描并同步这些路径；排除规则、连接证书等设置变化会中断当前轮次并重新扫描，避免用旧规则继续同步。

排除路径不会从主机传输；从机已有内容会保留。添加排除规则前已经传过去的内容不会自动清理，需在从机手动处理。移除规则后，主机同路径的文件重新参与同步；如果主机已删除原先同步过的路径，从机会按历史归属记录清理它。从机独有的路径仍保留。

## 数据行为

- 从机独有的文件和目录会保留；主机删除此前已同步的文件时，从机也会删除。文件删除只作用于从机 `replica_files` 中记录过的文件；同步过的目录记录在 `managed_dirs` 中，主机删除目录时先删已记录的文件，再从内向外删除空目录；目录中若有从机独有内容，目录和内容都会保留。从机本地修改了同路径普通文件时会被主机版本覆盖；开启历史备份时，覆盖或删除文件前旧版本进入 `.rsync/history/`，保留 7 天。历史保留为 0 时不备份，已有历史内容仍保留。
- 此前已同步的路径发生文件与目录互换时，在线增量与离线后的全量同步都会处理。全量替换目录前先检查整个子树，只有同步程序管理的内容才可清理；从机独有文件、空目录或排除内容会阻止替换并保留，需人工处理冲突。清理按有界分页进行，开启历史备份时旧文件先备份，中途退出后可重试。不要把 `.rsync` 目录复制到另一节点；每个节点都要单独执行 `init`。
- 支持普通文件和目录、4 MiB 分块校验与断点续传。不同步权限和所有权。主机扫描时跳过符号链接，不跟随链接或复制其目标；链接存在期间，从机同路径已有内容会保留。主机后来移除链接时，从机曾由主机同步的同路径普通文件会被清理，从机独有文件仍保留。从机已有的符号链接也会跳过并保留，相关路径不写入、不删除，其他文件继续同步。同步路径上遇到其他特殊文件会报错并停止该轮同步。
- 全量和增量扫描共用有界哈希批次，每批最多 64 项；达到 16 个待哈希文件或至少 2 个不小于 256 MiB 的文件时，主机最多使用 `hash_workers` 个线程并行计算文件哈希，默认 2 个，允许 1–8 个；少量大文件也可并行扫描，普通少量文件不创建线程池。后续扫描复用未变化文件的哈希缓存；若目录清单指纹未变化则直接复用已有清单。文件监控事件只扫描涉及的文件或目录；内容不变时不发送清单，内容变化时只发送变化项。文件监控不可用、监控库报告事件丢失或变更路径超过 5 万条时会退回完整扫描；扫描尚未提交时，失败事件与新事件合并也使用相同上限，全量标记生效后不再积累路径。已提交的增量任务保存在主机 SQLite `source_outbox` 中，按路径分页读取，不受内存事件队列大小限制。排除路径的文件监控事件不会中断同步。默认每 24 小时完整重新校验一次。`hash_workers` 只用于主机扫描；两端可分别调整 `verify_interval_secs`。
- 文件和目录以最多 512 项的有界批次协商，同时限制元数据约 4 MiB、小文件原始内容约 8 MiB；从机集中返回需要数据的文件。小于等于 64 KiB 的文件在批次内合并处理：最多暂存 32 个文件后使用 2 个线程并行落盘，每组文件及其父目录完成持久化、归属记录提交后才继续处理；整批处理完成后再发送确认；不足 32 个文件时不创建线程池。大文件仍按 4 MiB 块传输；同尺寸旧文件在请求数据前已校验且状态未变时，不再重复计算整文件哈希；若文件状态与缓存一致、缓存哈希已不同于主机，则直接进入分块复用，省去一次旧文件整文件读取，仍保留分块校验及最终完整校验。主机读取小文件时最多读取预期大小加 1 字节，扫描后文件突然变大会终止该轮同步，避免一次读入大文件。主机用 256 KiB 的读取缓冲区流式计算文件哈希，保留精确的 4 MiB 分块边界。扫描清单存放在 SQLite 中；从机按路径顺序校验批次，只需记住上一条路径，避免文件数增多时一直占用进程内存。默认每 24 小时完整扫描并向从机发送清单，以发现漏掉的文件事件和从机本地改动；主机重启后立即扫描本地目录，只有上次同步完整、从机代数和同步配置一致且清单未变化时才跳过重复发送。增量任务失败后仅重新检查未确认路径，不再因为传输失败而扫描整棵目录；未变化文件复用哈希缓存。主机重启发现未完成的增量时，会通过本地扫描补入停机期间的变化，再继续发送增量任务。首次同步、定时全量、配置或保护规则变化，以及对端同步代次异常时仍进行完整校对。由于从机本地改动不能仅靠代数发现，仍由定期完整校对检查。
- 从机完整校验会读取尚未校验的现有文件内容，校验结果在文件发布、暂存组处理及条目批次完成时提交，先保存归属记录再发送确认。中断后，只有本轮已提交、主机哈希及从机文件状态均未变化的文件可跳过重复哈希；完整清单处理成功后才更新上次完整校验时间。校验轮次保存在 `replica_files` 的 `verified_round` 字段中。`rsync status` 和 Web `/api/status` 提供本轮重新哈希文件数、字节数以及复用校验记录数；主机还提供最近一轮扫描和传输耗时 `last_scan_ms`、`last_transfer_ms`，单位为毫秒。
- 从机在替换文件前把发布意图写入现有 `staging` 表，文件归属提交后在同一事务中删除该记录。批次中断时保留已发布文件的归属；进程意外退出后，下一轮同步先核对待发布目标的实际内容，仅恢复哈希一致且校验期间未变化的普通文件，然后再处理删除。不会仅凭待发布路径接管从机独有内容。
- 网络控制帧和数据块有 2 分钟单次读写超时，TLS 握手最多 10 秒，握手后等待首帧最多 30 秒。TCP keepalive 在连接空闲约 60 秒后开始探测，主机关机后的半开连接通常会在随后约 30 秒内被从机释放。写入中的大文件按约 32 MiB 保存一次断点进度；异常中断时，最后一批未确认的数据可能重新传输，文件仍会在整文件校验通过后才替换。
- 每个主机进程一次只同步一组目录到一台从机，但可以在网页切换连接目标。文件名需要是 UTF-8；主机同步树内不能嵌套其他 `.rsync` 目录。运行账户必须能读写同步目录，且两台机器时钟应准确，以便 TLS 证书有效。
- 为限制单次清单占用，单文件最多 200,000 个 4 MiB 块，约 781 GiB；超出时主机会在扫描阶段报错。

## 端口安全与主机离线

从机同步端口只接受通过双向 TLS 认证的主机证书。首次配对时必须核对 CA 指纹；`.rsync` 目录权限为 `0700`，节点私钥为 `0600`，请仅让同步账户访问。协议只有固定的同步与程序升级帧，没有远程命令执行接口；非规范路径、重复或超额清单、过大的控制帧和超限升级包会被拒绝。未完成的 TLS 握手有并发上限和超时，避免单个慢连接长期占住监听流程。

建议从机绑定可供主机访问的地址，并在防火墙只允许主机 IP 访问同步端口。双向 TLS 保护身份和内容；防火墙还能减少公开端口受到的连接洪泛。不要把同步端口直接暴露到互联网。

主机离线时，从机继续监听并保留文件。主机重新运行后会主动连接并同步；中断的大文件从已保存的块继续。每个文件在完整校验后才替换；从机独有文件始终保留。中断期间整个目录树可能暂时处于部分更新状态。每个同步根目录同时只允许一个 `run` 进程；进程退出或关机后锁会由系统释放。

如需主机开机后自动恢复，在主机上配置 systemd 服务；从机也可用相同方式常驻，只需替换根目录：

```ini
[Unit]
Description=rsync source
Wants=network-online.target
After=network-online.target

[Service]
Type=simple
User=syncuser
ExecStart=/usr/local/bin/rsync run --root /data/source
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

将服务中的用户、程序路径和根目录改为实际值，保存为 `rsync-source.service` 后用 `systemctl enable --now rsync-source.service` 启用。从机可按相同方式建立 `rsync-replica.service`。即使网络在启动时尚未可用，程序也会持续重试。

## 代码结构

- `src/engine.rs`：主从连接、文件监控、同步调度、传输、删除、历史备份与发布恢复。
- `src/scan.rs`：全量与增量扫描、清单缓存。
- `src/state.rs`：数据库结构、文件归属、断点与发布记录。
- `src/web.rs`、`src/wire.rs`、`src/upgrade.rs`：Web 控制、通信协议和程序升级。

发送清单、文件元数据和删除路径时借用已有批次，避免深拷贝分块哈希；控制帧在序列化过程中限制为 16 MiB。扫描或校验中的文件若增长，最多读取初始大小加 1 字节后报错重试。文件监控使用不可变排除规则快照，仅在规则变化时重建，读写锁只覆盖快照指针交换。升级候选的版本输出和错误输出有独立上限，超限或超时会终止并回收候选进程。

## 开发验证

在主机和测试从机分别编译候选版本，使用独立的同步根目录、证书和空闲端口完成联调。按“首次配置”章节配对双方 CA 后，先启动测试从机，再启动测试主机；测试进程直接从命令行运行，不创建自启动服务。

测试时检查首次同步、多文件传输、大文件局部修改、目录删除、排除规则、符号链接跳过，以及从机独有文件是否保留。用 `sha256sum` 比对两端文件；用 `rsync status --root <测试目录>` 查看传输字节数和错误。结束后停止这两个测试进程，避免占用端口。不要用正式同步根目录做测试。
